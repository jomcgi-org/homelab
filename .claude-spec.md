# T2 Implementation: In-Guest Egress Proxy

Implement an HTTP proxy in the shotter guest that:

1. **Listens on 127.0.0.1:1024** (Chromium is pointed here via --proxy-server)

2. **Handles HTTP requests**: Both CONNECT (for HTTPS) and absolute-form (for HTTP)
   - Read request head up to \r\n\r\n
   - Parse method and target from first line
   - For CONNECT: target is host:port
   - For absolute-form: extract host:port from Host header, default port 80

3. **Maps public hosts to internal services** from environment variables:
   - Config comes from `SHOTTER_HOST_MAPPING` (JSON dict) and `SHOTTER_ALLOWLIST` (JSON list)
   - Example mapping: "jomcgi.dev" -> "monolith-public-frontend.monolith-public.svc.cluster.local:3000"
   - Example mapping: "private.jomcgi.dev" -> "monolith.monolith.svc.cluster.local:3000"
   - Fail closed: if env is absent or malformed, refuse all connections

4. **Hard allowlist** (critical security control):
   - Check the destination BEING DIALLED, not just the top-level requested host
   - This prevents redirects/subresources to unmapped destinations
   - Use exact matching only, never suffix or substring matching
   - Refuse before opening any vsock connection

5. **For allowed requests**:
   - Dial vsock CID 2 port 1025
   - Write one-line preamble: `mapped-host:port\n`
   - For CONNECT: respond with "HTTP/1.1 200 Connection Established\r\n\r\n"
   - For absolute-form: replay entire request head byte-for-byte (Host header must be preserved)
   - Copy bytes bidirectionally between client and upstream

6. **For refused requests**:
   - Close connection without writing preamble or dialling vsock
   - No partial connections, no side effects

## Tests (Go, in proxy_test.go)

Required cases, each asserting NO vsock dial occurs for refusals:
- Mapped host dials correct internal service, replayed head carries Host: jomcgi.dev
- api.github.com is refused, named explicitly
- Suffix lookalikes refused: evil-jomcgi.dev, jomcgi.dev.evil.com, staging.jomcgi.dev
- Redirect or subresource to unmapped destination refused even though top-level was mapped
- CONNECT to unmapped host refused
- Absent or malformed mapping env refuses everything

Use a mock for vsock to assert non-execution, not just error returns.
