# Grimoire Knowledge Audiences Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (or subagent-driven-development per repo default) to implement this plan task-by-task. Per CLAUDE.md there is NO local test loop: write tests with each task, self-review, commit, and defer all test execution to the end-of-plan CI run on the pushed branch.

**Goal:** Implement ADR services/013: audience rules on extracted entities, compiled into `derived` knowledge grants by a deterministic attach job, plus the per-campaign book blacklist spoiler gate.

**Architecture:** A new `audience_term` closed vocabulary and `entity_knowledge_audience` rules table are populated by deterministic seeding (spell classes/levels, location regions) and a separate entity-level LLM enrichment pass (DeepSeek v4 flash class model, marker-keyed by prompt version). An idempotent attach job matches PC attributes against rules and upserts `knowledge_grant` rows with `grant_source='derived'`. The read predicate is unchanged except for the campaign book blacklist exclusion. See `docs/decisions/services/013-grimoire-knowledge-audiences.md` for all rationale; this plan is mechanism only.

**Tech Stack:** Python (FastAPI + SQLModel via aspect_rules_py), Postgres (Atlas migrations in `projects/monolith/chart/migrations/`), Argo CronWorkflows via `app/jobs_main.py` Typer subcommands, hand-registered `py_test` targets in `projects/monolith/BUILD`.

**Sequencing constraint:** the LLM enrichment pass (Task 6) should only RUN in prod after the DeepSeek v4 flash re-extraction of the corpus settles, but all code here can merge before that. Nothing in this plan mutates extraction.

**Repo gotchas that WILL bite (from memory/CI history):**

-- ADR services/013: knowledge audiences, compiled grants, book blacklist.

-- Closed audience vocabulary. status='candidate' rows are LLM-proposed keys
-- awaiting DM review; the enrichment pass only matches status='active'.
CREATE TABLE grimoire.audience_term (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    kind TEXT NOT NULL CHECK (kind IN ('region', 'species', 'background', 'class')),
    key TEXT NOT NULL,
    display_name TEXT NOT NULL,
    aliases JSONB NOT NULL DEFAULT '[]'::jsonb,
    status TEXT NOT NULL DEFAULT 'active' CHECK (status IN ('active', 'candidate')),
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    UNIQUE (kind, key)
);

-- Corpus-level source of truth: "(entity) is known to (term) at (scope)".
CREATE TABLE grimoire.entity_knowledge_audience (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    entity_id UUID NOT NULL REFERENCES grimoire.entity(id) ON DELETE CASCADE,
    audience_term_id UUID NOT NULL REFERENCES grimoire.audience_term(id),
    min_level INTEGER,
    grant_scope TEXT NOT NULL CHECK (grant_scope IN ('full', 'partial', 'name_only')),
    revealed_details JSONB,
    origin TEXT NOT NULL CHECK (origin IN ('deterministic', 'llm', 'dm')),
    evidence_chunk_id UUID REFERENCES grimoire.knowledge_chunk(id),
    confidence REAL,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    UNIQUE (entity_id, audience_term_id)
);
CREATE INDEX idx_grimoire_eka_term ON grimoire.entity_knowledge_audience (audience_term_id);

-- Enrichment processed-marker, mirroring chunk_extraction semantics but
-- entity-keyed and versioned by explicit prompt_version (not prompt hash).
CREATE TABLE grimoire.entity_enrichment (
    entity_id UUID NOT NULL REFERENCES grimoire.entity(id) ON DELETE CASCADE,
    model TEXT NOT NULL,
    prompt_version TEXT NOT NULL,
    status TEXT NOT NULL CHECK (status IN ('ok', 'empty')),
    enriched_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    PRIMARY KEY (entity_id, model, prompt_version)
);

-- Grant provenance. Existing rows default to 'manual'.
ALTER TABLE grimoire.knowledge_grant
    ADD COLUMN grant_source TEXT NOT NULL DEFAULT 'manual'
        CHECK (grant_source IN ('manual', 'derived')),
    ADD COLUMN derived_from_audience_id UUID
        REFERENCES grimoire.entity_knowledge_audience(id) ON DELETE SET NULL;

-- DM-retracted derived grants are never re-attached.
CREATE TABLE grimoire.knowledge_grant_suppression (
    player_character_id UUID NOT NULL REFERENCES grimoire.player_character(id) ON DELETE CASCADE,
    entity_id UUID NOT NULL REFERENCES grimoire.entity(id) ON DELETE CASCADE,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    PRIMARY KEY (player_character_id, entity_id)
);

-- Spoiler gate: blacklisted books are invisible to players in this campaign
-- (grants override per-entity); the attach job skips them entirely.
CREATE TABLE grimoire.campaign_book_blacklist (
    campaign_id UUID NOT NULL REFERENCES grimoire.campaign(id) ON DELETE CASCADE,
    book_id TEXT NOT NULL REFERENCES grimoire.book(id) ON DELETE CASCADE,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    PRIMARY KEY (campaign_id, book_id)
);

-- Subject attributes the attach job matches on (class_name/level already exist).
ALTER TABLE grimoire.player_character
    ADD COLUMN species TEXT,
    ADD COLUMN background TEXT,
    ADD COLUMN home_region TEXT;

-- Seed the closed vocabulary: 5e SRD classes, species, backgrounds.
-- Regions deliberately start empty; they arrive via deterministic seeding
-- candidates and DM curation (corpus regions are setting-specific).
INSERT INTO grimoire.audience_term (kind, key, display_name) VALUES
    ('class', 'barbarian', 'Barbarian'), ('class', 'bard', 'Bard'),
    ('class', 'cleric', 'Cleric'), ('class', 'druid', 'Druid'),
    ('class', 'fighter', 'Fighter'), ('class', 'monk', 'Monk'),
    ('class', 'paladin', 'Paladin'), ('class', 'ranger', 'Ranger'),
    ('class', 'rogue', 'Rogue'), ('class', 'sorcerer', 'Sorcerer'),
    ('class', 'warlock', 'Warlock'), ('class', 'wizard', 'Wizard'),
    ('species', 'human', 'Human'), ('species', 'elf', 'Elf'),
    ('species', 'dwarf', 'Dwarf'), ('species', 'halfling', 'Halfling'),
    ('species', 'dragonborn', 'Dragonborn'), ('species', 'gnome', 'Gnome'),
    ('species', 'half-elf', 'Half-Elf'), ('species', 'half-orc', 'Half-Orc'),
    ('species', 'tiefling', 'Tiefling'), ('species', 'orc', 'Orc'),
    ('species', 'goliath', 'Goliath'), ('species', 'aasimar', 'Aasimar'),
    ('background', 'acolyte', 'Acolyte'), ('background', 'charlatan', 'Charlatan'),
    ('background', 'criminal', 'Criminal'), ('background', 'entertainer', 'Entertainer'),
    ('background', 'folk-hero', 'Folk Hero'), ('background', 'guild-artisan', 'Guild Artisan'),

**Step 1: Failing tests** for `attach_derived_grants(session, campaign_id=None, player_character_id=None) -> dict`:
- A PC with `species='elf'` gets a derived grant for an entity with an elf audience rule; `class_name='wizard', level=3` matches `min_level<=3` rules only; level-up to 5 then re-run adds the level-5 rules.

**Step 2: Implement.** Matching is a join: PC attribute tuple resolved through `resolve_term` once, then rules filtered by term ids + `min_level <= pc.level`. Grant upsert sets `grant_source='derived'`, `derived_from_audience_id`, scope from the rule.

**Step 3: DM retract semantics:** modify the existing grant-delete path in `projects/monolith/grimoire/router.py` so deleting a `derived` grant also writes a `knowledge_grant_suppression` row (manual grant deletion does not). Test in `router_test.py`.
