# INFRA-KEDA — Deploy KEDA event-driven autoscaler

**Unit:** INFRA-KEDA · **Status:** shipped (manifests inert pending central wiring)
**Classification:** [auto-merge] (pure new-file) · **Date:** 2026-05-30
**Wavefront:** 1 · **Branch:** `feat/lakehouse-infra-keda`

Greenfield deploy of KEDA per ADR `agents/015` §"Worker pools, not the orchestrator".
KEDA was verified **absent** in Wavefront 0 (no `keda` namespace, no
`scaledobjects.keda.sh` CRD, no pods). This unit stands KEDA up and installs its CRDs;
the actual `ScaledObject`s for worker pools come in a later wavefront (Wavefront 4) and
are **not** created here.

### Values decisions

- **CRDs installed** (`crds.install: true`, chart default kept). Renders all 6 KEDA
  CRDs including `scaledobjects.keda.sh`, `scaledjobs.keda.sh`,
  `triggerauthentications.keda.sh` / `clustertriggerauthentications.keda.sh`,
  `cloudeventsources.eventing.keda.sh`, `clustercloudeventsources.eventing.keda.sh` —
  Wavefront 4's worker autoscalers depend on these being present.
- **No NetworkPolicies** (`networkPolicy.enabled: false`, default kept explicit) — the
  `keda` namespace will be Linkerd-meshed; K8s NetworkPolicies break meshed traffic
  (port 4143 mismatch, per `feedback_linkerd_networkpolicy.md`).
- **Prometheus metrics enabled** on port 8080 for operator, metrics apiserver, and
  webhooks (`prometheus.{operator,metricServer,webhooks}.enabled: true`). SigNoz
  autodiscovers via `prometheus.io/scrape` pod annotations (port 8080, path /metrics),
  matching the seaweedfs pattern. ServiceMonitor/PodMonitor CRDs are **not** used (not
  installed in this cluster).
- **Kyverno OTEL annotation** pre-populated on all three pods
  (`otel.injected-by: kyverno/inject-otel-env-vars`) to match the cluster mutation and
  prevent ArgoCD drift (matching nats/seaweedfs).
- **Modest homelab resources** — requests 50m/64Mi (operator, metricServer), 25m/32Mi
  (webhooks); limits 500m/256Mi and 200m/128Mi respectively. The chart ships 1 CPU /
  1000Mi limits per component, oversized for our load; raise once worker-pool
  autoscaling load is observed.
- **Security:** KEDA is secure-by-default — all three components render with
  `runAsNonRoot: true`, `readOnlyRootFilesystem: true`, `drop: [ALL]` caps, and
  `seccompProfile: RuntimeDefault`. No security overrides needed.

## Deviations

1. **`semgrep_exclude_rules = ["require-tmp-emptydir"]` in BUILD.** KEDA's components run
   `readOnlyRootFilesystem: true` + `runAsNonRoot: true` but mount only `/certs` (no
   `/tmp` emptyDir). The repo's `require-tmp-emptydir` rule (WARNING) has no path
   restriction, so it scans the rendered manifest and would fail the
   `semgrep_manifest_test` (the test runner fails on **any** finding regardless of
   severity). The KEDA Go binaries do not write to `/tmp`, and the upstream chart
   exposes no wrapper value to add a `/tmp` emptyDir without custom `extraVolumes`
   plumbing — so the rule is excluded, consistent with how nats/seaweedfs exclude
   security rules they cannot satisfy via wrapper values.
2. **Single `values.yaml`** (no `values-prod.yaml`), per this unit's spec. nats and
   seaweedfs carry a second prod overlay; KEDA needs no env split.

## Deferred (out of scope for this unit)

- **Central wiring.** Per the additive-build convention, this unit does **not** edit
  `projects/platform/kustomization.yaml` or regenerate
  `projects/home-cluster/kustomization.yaml`. The KEDA Application is therefore **inert
  until** the orchestrator wires `projects/platform/keda` into the platform
  kustomization and regenerates the root after merge. This is intended.
- **`ScaledObject`s / `ScaledJob`s for worker pools** — Wavefront 4
  (`DEPLOY-*` worker autoscalers). KEDA only provides the control plane + CRDs here.
- **`TriggerAuthentication`** for NATS JetStream scalers — created alongside the worker
  ScaledObjects in Wavefront 4.
