# Semgrep Scan Perf Comparison Page Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task.

**Goal:** A private monolith dashboard page that shows side-by-side scan performance (runtime + findings) for the same commit/PR/main-full-scan, comparing our self-hosted Route B scans against Semgrep Managed Scans (SMS).

**Architecture:** A `semgrep.scan_perf` Postgres table is populated two ways: `report.py` writes the authoritative Route B row at scan-complete (it already holds the real engine `total_time`), and a scheduled harvest job pulls SMS scans from the Semgrep API (findings sweep -> `GET /api/agent/scans/{id}`) and upserts them. A pure-Python comparison layer pairs Route B <-> SMS rows by commit (then ref, then nearest main full-scan by date). A private SvelteKit page at `/private/perf` renders the side-by-side table via a `/api/semgrep/perf` JSON endpoint.

**Tech Stack:** Python (FastAPI, SQLModel + psycopg v3 sync), SvelteKit (private dashboard, time-of-day theme), Atlas migrations, Argo CronWorkflow, Semgrep App API.

## Background: the two data sources (read before starting)

- **Route B (ours):** self-hosted interfile/single-file scan on the fc-invoke daemon. We own `report.py`; the authoritative runtime is the `scan_execution_duration` we already compute. Reports to real project `jomcgi/homelab` (post-cutover). On the App, our scans currently carry `environment = SCAN_ENVIRONMENT_UNSPECIFIED`.
- **SMS (Semgrep Managed Scans):** run on Semgrep's infra. On the App, `environment = SCAN_ENVIRONMENT_MANAGED_SCANS`.
- **API facts (verified 2026-07-11):**
  - Scan record: `GET https://semgrep.dev/api/agent/scans/{scan_id}` -> `{"scan": {id, repositoryId, deploymentId, startedAt, completedAt, exitCode, commit, isFullScan, status, findingsCounts:{total,code}, totalTime, branch, repositoryUrl, cliVersion, environment, scmType, ...}}`. **`totalTime` is the real runtime (seconds).** `startedAt`/`completedAt` for our scans are ~1s apart (they mark our reporting window, not the scan) so DO NOT compute duration from them; trust `totalTime`.
  - Findings: `GET https://semgrep.dev/api/v1/deployments/jomcgi/findings?repos=jomcgi/homelab&page_size=3000` -> `{"findings":[{first_seen_scan_id, ref, repository, ...}]}`. **There is NO list-scans endpoint** — the only way to discover SMS scan IDs is harvesting distinct `first_seen_scan_id` from findings (verified: 166 distinct scan IDs across 581 open findings = a solid one-time backfill).
  - Auth: Bearer token. Deployment slug `jomcgi`, numeric deployment id `47408`.
- **Coverage caveat (surface this on the page):** SMS coverage is best-effort — we only see SMS scans that left a still-open finding. Route B coverage is complete (captured at report time). A zero-finding SMS scan is invisible, but it has nothing to compare against anyway.

-- semgrep.scan_perf: one row per Semgrep scan we track, for the private
-- Route B vs Semgrep Managed Scans performance comparison page.
-- Two writers: report.py inserts Route B rows at scan-complete (authoritative
-- runtime); a scheduled harvest upserts SMS rows from the Semgrep API.
CREATE SCHEMA IF NOT EXISTS semgrep;

CREATE TABLE IF NOT EXISTS semgrep.scan_perf (
    id                 BIGSERIAL PRIMARY KEY,
    scan_id            BIGINT NOT NULL UNIQUE,
    -- normalized source: 'route-b' (ours) or 'managed-scans' (SMS)
    environment        TEXT NOT NULL DEFAULT '',
    -- raw Semgrep enum for provenance, e.g. SCAN_ENVIRONMENT_MANAGED_SCANS
    raw_environment    TEXT NOT NULL DEFAULT '',
    is_full_scan       BOOLEAN NOT NULL DEFAULT FALSE,
    branch             TEXT NOT NULL DEFAULT '',
    scan_ref           TEXT NOT NULL DEFAULT '',
    commit_sha         TEXT NOT NULL DEFAULT '',
    total_time         DOUBLE PRECISION NOT NULL DEFAULT 0,
    findings_total     INTEGER NOT NULL DEFAULT 0,
    cli_version        TEXT NOT NULL DEFAULT '',
    scan_started_at    TIMESTAMPTZ,
    scan_completed_at  TIMESTAMPTZ,
    fetched_at         TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    created_at         TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    CONSTRAINT scan_perf_environment_valid
        CHECK (environment IN ('route-b', 'managed-scans', ''))
);

CREATE INDEX IF NOT EXISTS scan_perf_commit ON semgrep.scan_perf (commit_sha);
CREATE INDEX IF NOT EXISTS scan_perf_ref ON semgrep.scan_perf (scan_ref);
CREATE INDEX IF NOT EXISTS scan_perf_env_full_completed

**Step 1: Define the model + insert/upsert**

```python
# perf_store.py
from __future__ import annotations
from datetime import datetime
from typing import Optional
from sqlmodel import Field, SQLModel, Session, select


class ScanPerf(SQLModel, table=True):
    __tablename__ = "scan_perf"
    __table_args__ = {"schema": "semgrep"}

    id: Optional[int] = Field(default=None, primary_key=True)
    scan_id: int = Field(index=True)
    environment: str = ""          # 'route-b' | 'managed-scans'
    raw_environment: str = ""
    is_full_scan: bool = False
    branch: str = ""
    scan_ref: str = ""
    commit_sha: str = ""
    total_time: float = 0.0
    findings_total: int = 0
    cli_version: str = ""
    scan_started_at: Optional[datetime] = None
    scan_completed_at: Optional[datetime] = None


def upsert_scan_perf(session: Session, row: ScanPerf) -> None:
    """Insert or update by scan_id. Route B rows (report.py) are authoritative
    on total_time; the harvest must NOT overwrite a route-b row's total_time
    with the API's rounded value. So: on conflict, only fill missing fields and
    never downgrade environment from 'route-b'."""
    existing = session.exec(
        select(ScanPerf).where(ScanPerf.scan_id == row.scan_id)
    ).first()
    if existing is None:
        session.add(row)
    else:
        # do not clobber an authoritative route-b row with harvested SMS-style data
        if existing.environment == "route-b" and row.environment != "route-b":
            return
        for f in ("environment", "raw_environment", "is_full_scan", "branch",
                  "scan_ref", "commit_sha", "total_time", "findings_total",
                  "cli_version", "scan_started_at", "scan_completed_at"):
            setattr(existing, f, getattr(row, f))
        session.add(existing)
    session.commit()
```

**Step 1: pure matching** — input: two lists of row-dicts (route-b, managed-scans). Output: ordered comparison rows.

Matching rule (commit -> ref -> date), bucketed by `is_full_scan`:
1. **Commit match:** a route-b row and an SMS row with the same `commit_sha` and same `is_full_scan` -> one row.
2. **Ref match:** among still-unmatched, same `scan_ref` + `is_full_scan` (handles a PR both sides scanned at slightly different commits) -> pair the closest by `scan_completed_at`.
3. **Date match (main full-scans only):** among still-unmatched `is_full_scan=True, branch='main'`, pair each route-b with the nearest-in-time SMS by `scan_completed_at`.
4. Unmatched rows are emitted as one-sided rows (route_b_time set, sms_time null, or vice-versa) so the page can show "no counterpart".
