| [056 - Agent-Authored Walkthroughs: the Diff is Fact, the Points are Testimony](agents/056-agent-authored-walkthroughs.md) | A session's changes walkthrough is agent-authored typed output (a `RATIONALE` trailer parsed fail-closed next to `parse_review_verdict`), never reconstructed from a commit range: the diff is fact, the agent's points are testimony, quoted and attributed, cross-checked against the diff so an unexplained file flags (never blocks the reviewer verdict, which would make testimony load-bearing for routing) and a point naming an absent file gets a contradiction marker, the `claims.js` juxtapose-never-merge pattern reused. | [058 - The Voice Companion: a Ledger-First Screen the Conversation Drives, Never Load-Bearing](agents/058-voice-driven-companion-screen.md) | A parallel screen a voice session grabs over MCP, where four `voice_ui_*` tools conjure read-only remounts of the console's run and walkthrough surfaces onto a stage keyed to what is being said right now, and every call accepts and no-ops with no companion open so nothing in the voice loop can ever depend on a screen. Every `voice_ui_*` call writes one durable ledger row before anything renders and the companion polls that table, which makes "no surface without a ledger row" a SQL-checkable invariant rather than a review convention, gets the audit trail for free since transport and persistence are the same choice, and sidesteps the tripwire under an in-process SSE fanout (it works only at `backend.replicas: 1`, and the chart already carries a disabled `backend.autoscaling` block that would drop surfaces silently once enabled); ADR 049's poll shape is reused while its four-hop-buffering reasoning is explicitly disclaimed as not applying, since these events originate in the monolith itself. `attach` binds a named session or mints one and returns its id (a bare re-attach returns the existing binding, so a reconnecting tab cannot spawn sessions), the latest explicit attach wins so no call in the contract needs a refusal path, and authorization is two tiers: reads and attached-session sends on voice alone, everything else raises `voice_ui_ask`, with the clicked and spoken answers resolving the same gate through the same `agent_session_send` path (a third click-only tier was rejected because it depends on a hand-maintained list that decays). Decay and auto-surfacing are engine behaviour rather than tools, so the invariant keeps exactly one way for a card to appear, and surfaces are never inferred from the session record, ADR 056's lesson applied one level up. v1 **records** the MCP principal and gates on nothing. Verification already ships (#4955 wraps the MCP mount in `PrincipalMiddleware`, and `current_principal()` has no consumers outside `auth/` yet), but two facts stop it carrying a gate: no token has been observed arriving on the claude.ai path, measured on a cold JWKS cache, so the principal is anonymous in practice and a real gate would refuse every real call; and on the SSE transport the principal is pinned to the stream-opener rather than the message, so it identifies the connection and not the caller. So the ledger records `subject` and `authority` from the first commit, which makes the anonymity observable rather than assumed, makes this the auth domain's first consumer, and turns the eventual gate into a comparison on data already written. A disabled flag was rejected as the declared-but-unwired failure the rest of the ADR avoids; the private tier's Cloudflare Access gate remains the real control, and attach only selects among sessions the viewer may already see. Closes the decision checklist in #4977. Accepted |
