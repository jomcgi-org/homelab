# Supplemental tests in a cloud session

`tools/setup-local-tests.sh` installs Go, protoc, Go protobuf plugins and a
Python test venv in `/workspace/.cloud/local-tests`. Use it in a Linux x86_64
cloud environment where language tools are missing. It requires Bash, curl,
Python 3.12+ and uv, plus write access to `/workspace/.cloud` and access to the
public package sources. It does not install those prerequisites.

## Preserve the setup

Once this script is in the environment's checkout, put this command in its
saved setup command:

```bash
bash /workspace/homelab/tools/setup-local-tests.sh /workspace/homelab
```

The optional argument selects the repository whose version declarations to
use. The script itself defaults to its own checkout.
No executor-local script or companion file needs to be copied: `env.sh` and
`constraints.txt` are generated by the script. A new session can reconstruct
the tools by running it again.

In each shell that needs Go:

```bash
source /workspace/.cloud/local-tests/env.sh
```

The venv's Python is `/workspace/.cloud/local-tests/venv/bin/python`. Setup
makes no changes to shell startup files, saved environment settings, secrets,
network configuration, the shared bootstrap or CI defaults. It runs no tests.

## What this validates

The supported repository feedback loop remains `ci`: local formatting,
selective generation and ratchets, followed by hosted BuildBuddy tests.
Targeted pytest is an advisory check permitted by `docs/agents/reference.md`.
Direct Go tests are also supplemental evidence. They do
not reproduce Bazel's hermetic dependency graph, target selection, hosted
services or full CI coverage. No global `SKIP_REMOTE` setting is added.

For Ember, the Go protobuf stubs are tracked (`node.pb.go` and
`node_grpc.pb.go`, #7066), so the tests need no generation step:

```bash
source /workspace/.cloud/local-tests/env.sh
go test ./projects/embervm/noded/server \
  ./projects/embervm/noded/fcvm/driver ./projects/embervm/noded/config
```

After editing `node.proto`, regenerate the two stubs for a local run:

```bash
protoc -I projects/embervm/proto \
  --go_out=projects/embervm/proto --go_opt=paths=source_relative \
  --go-grpc_out=projects/embervm/proto --go-grpc_opt=paths=source_relative \
  embervm/node/v1/node.proto
```

CI's `update_go_stubs` writeback and `check_go_stubs` stay authoritative for
the committed bytes.

For a targeted factory check:

```bash
PYTHONPATH=projects/monolith PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 \
  /workspace/.cloud/local-tests/venv/bin/python -m pytest \
  -p pytest_asyncio.plugin -q \
  projects/monolith/factory/orchestration/factory_rollout_test.py \
  projects/monolith/factory/orchestration/factory_landing_test.py
```

The selected Python dependency set supports these factory tests. Other tests
may need more packages; setup does not claim to install every repository
runtime dependency.

## Versions and sources

Versions come from the selected checkout, so later checkouts can select
different ones.

| Tool | Version source | Download and verification |
| --- | --- | --- |
| Go | `go.mod` | Official `go.dev/dl` archive, checked against its release manifest SHA-256 |
| protoc | `bazel/erlang/repositories.bzl` | Official `protocolbuffers/protobuf` GitHub release, checked against the pinned SHA-256 |
| protoc-gen-go | `go.mod` | Official `google.golang.org/protobuf` module |
| protoc-gen-go-grpc | `go.mod` | Official `google.golang.org/grpc/cmd/protoc-gen-go-grpc` module |

Python packages come from PyPI through uv, with version constraints extracted
from `bazel/requirements/all.txt`. This supplemental install does not enforce
the lockfile's archive hashes.
