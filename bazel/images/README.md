# bazel/images

Code-generation and validation scripts that keep two auto-generated build
artifacts in sync with the repository's project layout and Bazel build graph.

| Artifact                                   | Generated by               | Role                                                            |
| ------------------------------------------ | -------------------------- | --------------------------------------------------------------- |
| `bazel/images/BUILD`                       | `generate-push-all.sh`     | `push_all` multirun: every OCI image and Helm chart push target |
| `projects/home-cluster/kustomization.yaml` | `generate-home-cluster.sh` | ArgoCD root app-of-apps Kustomization (GitOps entry point)      |

Neither of these files should be edited by hand. Both carry a `DO NOT EDIT`
header and are regenerated by `format` (or `fast-format.sh`).

## Scripts

| Script                         | Bazel target                               | Output                                                                                                                                                                                 |
| ------------------------------ | ------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `generate-push-all.sh`         | `//bazel/images:generate-push-all`         | `bazel/images/BUILD` with a `push_all` multirun over every `go_image`, `py3_image`, `apko_image`, `apko_nginx_frontend`, `oci_push`, and `helm_chart(publish=True)` target in the repo |
| `generate-home-cluster.sh`     | `//bazel/images:generate-home-cluster`     | `projects/home-cluster/kustomization.yaml` listing every `projects/*/deploy/` directory and top-level aggregator discovered on disk                                                    |
| `validate-generate-scripts.sh` | `//bazel/images:validate-generate-scripts` | (no output) validates that the grep-based generators agree with `bazel query`                                                                                                          |

Both generator targets (`generate-home-cluster`, `generate-push-all`) run inside
the `//bazel/tools/format:format` multirun alongside code formatters and
Gazelle. They respect `BUILD_WORKSPACE_DIRECTORY` (set by `bazel run`) and fall
back to `git rev-parse --show-toplevel`, so they work as Bazel targets and as
plain shell calls.

## CI wiring

The CI "Format check" action (see `buildbuddy.yaml`) runs
`bazel run //bazel/tools/format:format`, then immediately runs
`./bazel/images/validate-generate-scripts.sh`. If any generator output has
drifted from the real build graph, CI fails with a diff.

Nothing runs `bazel run //bazel/images:push_all` any more, on either branch.
`bazel run` materialises every command's runfiles before the first command
executes, so running the whole multirun pulls all ~24 dual-arch images out of
CAS even when every action is a cache hit.

PR branches (`pr-checks`) prove the images build and publish nothing:

```
bazel build //bazel/images:push_all --config=ci
bazel run //bazel/images:push_charts --config=ci --stamp
```

main (`deploy`) publishes through `bazel/images/push/push-changed.sh`, which
builds the same way, reads each image's content digest from
`//bazel/images/digests:manifest`, and runs only the `*.push` targets whose
content is not already in the registry. Charts publish after the images rather
than concurrently with them.

Skipping is safe because image digests are content-stable and every chart here
deploys `repository@digest`: a push over identical bytes would only add another
build-timestamped tag that nothing reads. Anything the manifest does not cover
is pushed regardless.

## `generate-home-cluster.sh` and GitOps

`projects/home-cluster/kustomization.yaml` is the ArgoCD root app-of-apps. The
script discovers two kinds of entries: top-level aggregator directories (a
`projects/<name>/` that contains child `kustomization.yaml` files) and
individual `deploy/` directories up to two levels deep. The result is sorted and
deduplicated, and each path is written as a relative `../../projects/...`
resource. ArgoCD applies this file to the cluster; adding or removing a
`deploy/kustomization.yaml` only takes effect once `format` regenerates this
file and the change is merged.

## Drift detection

`generate-push-all.sh` uses `grep` and `awk` to scan BUILD files rather than
loading the Bazel build graph. `validate-generate-scripts.sh` runs the
corresponding `bazel query` calls (`kind("oci_push", //...)`,
`kind("apko_push", //...)`, `kind("helm_push", //...)`) and diffs the results.
Any target that the grep heuristic misses fails CI immediately.
`generate-home-cluster.sh` does
not have a Bazel query equivalent (its inputs are filesystem paths), so
validation checks that the output is non-empty and contains at least one
resource path.

## Conventions

- Run `format` after adding, removing, or renaming any image or chart target.
  The generators pick up the change automatically.
- Do not hand-edit `bazel/images/BUILD`. It carries a generated header, and the
  next `format` run will overwrite manual changes.
- When `validate-generate-scripts.sh` fails in CI, check which BUILD files
  changed, re-run `format` locally, and push the regenerated files in the same
  commit as the build change.
