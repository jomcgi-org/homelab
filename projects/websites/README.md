# websites

Static sites built with Bazel and deployed to Cloudflare Pages via CI.

## Sites

| Directory          | Framework          | Cloudflare Pages project | Live URL                  |
| ------------------ | ------------------ | ------------------------ | ------------------------- |
| `jomcgi.dev/`      | Astro + React      | `jomcgi-dev`             | https://jomcgi.dev        |
| `docs.jomcgi.dev/` | VitePress          | `docs-jomcgi-dev`        | https://docs.jomcgi.dev   |

### jomcgi.dev

Personal site. Built with Astro (Vite internally), React components, and Tailwind. Pages:

| Path           | File                              | Description                                    |
| -------------- | --------------------------------- | ---------------------------------------------- |
| `/`            | `src/pages/index.astro`           | Homepage with live homelab stats from the cluster API |
| `/engineering` | `src/pages/engineering.astro`     | Homelab architecture detail                    |
| `/cv`          | `src/pages/cv.astro`              | CV rendered from `src/assets/cv.md`            |
| `/stargazer`   | `src/pages/stargazer.astro`       | Dark sky locations in Scotland with forecasts  |
| `/justin-demo` | `src/pages/justin-demo.astro`     | Demo page                                      |
| `/nelly-demo`  | `src/pages/nelly-demo.astro`      | Demo page                                      |

The Bazel target `//projects/websites/jomcgi.dev:build` runs Astro and produces a
`dist/` directory. Deployment to Cloudflare Pages is via the `jomcgi.push`
target, generated by the `wrangler_pages` macro (see
[`bazel/wrangler/defs.bzl`](../../bazel/wrangler/defs.bzl)).

### docs.jomcgi.dev

Architecture documentation and ADRs for this repo. Built with VitePress from
Markdown sources in `docs/` (mounted at the `docs` path in the built site).
Navigation covers architecture pages (services, security, observability, alerting,
contributing, agents) and an ADR sidebar generated by
`bazel/images/generate-docs-sidebar.sh`.

Deployment uses the `vitepress_site` macro from
[`bazel/vitepress/site.bzl`](../../bazel/vitepress/site.bzl), which runs a
five-step pipeline: assemble content, generate a path map, rewrite cross-repo
links, run `vitepress build`, then push via `wrangler pages deploy`. See
[`bazel/vitepress/README.md`](../../bazel/vitepress/README.md) for the full
pipeline description and public API.

A Python test (`config_links_test`) validates that every link in the VitePress
config sidebar points to a file that actually exists.

## Shared CSS

`shared/` contains CSS design tokens (`tokens.css`), a reset (`reset.css`), and
shared component styles (`components.css`). These are exposed as the
`//projects/websites/shared:css` js_library target and used by both sites and
the monolith frontend.

## Build and deploy

Both sites deploy to Cloudflare Pages. All traffic reaches them through
Cloudflare, with no direct origin exposure.

The top-level multirun target:

```
bazel run //projects/websites:push_all_pages
```

deploys both sites in parallel (alongside hikes and trips, which have their own
frontend directories). This target is auto-generated by
`bazel/images/generate-push-all-pages.sh` and is what BuildBuddy CI runs on every
push to `main`.

Individual site pushes:

```
bazel run //projects/websites/jomcgi.dev:jomcgi.push
bazel run //projects/websites/docs.jomcgi.dev:docs.push
```

Both require `CLOUDFLARE_API_TOKEN` in the environment (read by wrangler).
