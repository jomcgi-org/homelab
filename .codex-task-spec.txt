# Task: Make report_distress available in the agent tier

## Summary

`report_distress` cannot be added to the agent tier's tool catalogue because it currently reaches the private `agent` domain through `knowledge/mcp.py`'s `_notify` helper, which calls `agent.api.notify`. The agents binary prunes all of `agent/**`, so the import fails at call time (function-local import).

The solution is to move the notification path to `projects/monolith/shared/notify.py` (tier-portable, no domain dependencies), update imports everywhere, un-prune two chat files that the outbox producer needs, and add the tool.

## Implementation tasks

1. **Create `projects/monolith/shared/notify.py`**
   - Copy the body of `projects/monolith/agent/notify.py` (33 lines) verbatim in behavior
   - Read `MONOLITH_AGENT_DISCORD_DEFAULT_CHANNEL_ID` env var instead of importing `agent.config.load_settings`
   - Import `enqueue_message` from `chat.outbox` directly instead of `chat.api`
   - Keep `_enqueue_sync` helper and its docstring comment about not running sync Session on event loop
   - Keep the comment explaining that the outbox is a leader-only singleton

2. **Update `projects/monolith/agent/notify.py`**
   - Become a thin re-export: `from shared.notify import notify`
   - Preserve the public signature and behavior completely so `agent.api.notify` keeps working

3. **Update `projects/monolith/knowledge/mcp.py`** in `_notify` function (around line 112)
   - Change from: `from agent.api import notify as agent_notify`
   - Change to: `from shared.notify import notify as _notify_impl`
   - Call: `return await _notify_impl(message, level)`
   - Update docstring: replace the explanation of why report_distress CANNOT join the agent tier with a note that the notification path lives in `shared` precisely so both tiers can use it, and that function-local imports into pruned domains fail at call time not build time

4. **Update `projects/monolith/BUILD`**
